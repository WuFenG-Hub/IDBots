# SimpleLog 时间线（按 taskid 聚合）

一个只读的查看页：把链上 `/protocols/simplelog` 的过程记录按任务锚点（`taskid`，没有链上锚点时用 `taskkey`）聚合成一条条时间线，用来回答「这个任务上谁在什么时刻做了什么、状态如何、交付物在哪」。

SimpleLog 是过程记录层，知识层是 simplenote——本应用只看前者。它读链、不写链：不签任何请求、不提交任何 pin、不请求钱包或本地文件能力。

## 结构

- `index.html`：唯一入口，左侧任务锚点列表 + 右侧时间线
- `app.js`：取数与渲染（发现通道 + 正文通道、并发读回、侧栏/时间线/交付清单渲染）
- `simplelog-core.js`：纯逻辑（无 DOM、无依赖）——URI 解包与校验、记录准入、分组与排序、交付清单并集、更正识别。同一份文件既在页面里跑，也能被 Node 测试直接 require
- `app.css`：样式，单文件、无外部依赖

## 数据来源与读回约定

- **发现通道**：`GET /pin/path/list?path=/protocols/simplelog`，按 `nextCursor` 翻页。它只回答「有哪些条目」；列表返回的滚动摘要字段一律不参与展示与统计，`total` 不可信，不做判据。
- **正文通道**：`GET /content/<pinId>`，这是记录字段的唯一忠实来源。单次 404 视为索引延迟而不是未写入：读取在 60 秒窗口内每 5 秒重试一次。窗口内仍取不到正文的条目会被单独列为「读回失败」，不计入任何分组统计，页面上一条也不少地列出来。
- 同一任务下的记录按链上时间升序（日志顺读），任务之间按最后活动时间倒序。

## 记录准入与展示口径

- 准入（读取侧）：`v` 为 1、`kind` 与 `summary` 非空、`taskid` 或 `taskkey` 至少一项。字段缺失的条目按「非记录」处理，不进入时间线，但在读回失败清单里可见。
- 未知 `kind` 按 `note` 呈现（协议规定消费方须容忍自由值）。
- `deliverables` / `refs` 是链上 URI 数组。数组项若被包成 Markdown 链接（`[pin://X](pin://X)`）、反引号或尖括号，本应用按**链接目标**解包成裸 URI 再校验；缩略、占位符、Web2 URL 会被丢弃而不是展示成链接。包装是渲染形态，目标才是交付物。
- 「交付清单」面板是当前任务所有记录 `deliverables` 的**并集**，按 pinid 去重，保留每条的首发者。
- 更正：`summary` 以「更正：」开头的记录带「更正」标记，并在面板里单列。本视图**不隐藏**被更正的条目——它按时间序如实展示原始日志，取代关系留给读者与工具自行判定。

## URL 参数（hash 路由）

- `#/task/<label>`：选中某个任务锚点；`label` 是 `taskid`（完整裸 pinId）或 `taskkey` 原文，需 URL 编码。例：`#/task/b0eb2dd4…i0`
- 无 hash 时默认选中最近有活动的任务。

## 二次开发注意

- 纯逻辑改动集中在 `simplelog-core.js`，它也是被测试直接加载的那份；`app.js` 只做 DOM 与网络。
- 记录准入与 URI 解包规则必须与宿主台账/写入工具保持一致：这里放宽或收紧，都会和链上其他消费方产生口径差。改动时同步跑 `tests/simpleLogTimelineApp.test.mjs`。
- API 基址目前写死公共 `manapi.metaid.io`（与仓库内其它内置查看页同一姿态）。若宿主提供了索引器基址配置，应按配置优先、公共地址只作回退。
- 页面所有插值都经 `escapeHtml`；新增渲染路径时保持这条，别把链上原文直接拼进 DOM。
