## 2. Remaining opportunities

**Superseded by the 2026-08-09 gap audit** (`docs/analysis/2026-08-09-sdk-ui-gap-audit.md`),
which re-checks everything against SDK 0.3.221. Short version of the ranked backlog:

1. Subagent panel controls — `stopTask()` / `backgroundTasks()` (kill/background from UI).
2. ~~Surface dropped events~~ — ✅ done (this branch): `compact_boundary`, `notification`,
   `informational`, `permission_denied`, `conversation_reset`, `rate_limit_event` are
   surfaced as structured system messages; `thinking_tokens` feeds the usage chip;
   `session_state_changed` / `files_persisted` are explicit log-only.
3. Mid-session model switch via `setModel()` (same-provider only).
4. Live per-session MCP controls (`reconnectMcpServer` / `toggleMcpServer` / `mcpServerStatus`).
5. `betas: ['context-1m-2025-08-07']` behind the direct-Anthropic path.

## 3. Deliberately deferred (do not adopt)

- **CLI-native sandbox** — IDBots has its own QEMU micro-VM sandbox; SDK sandbox is Linux-container-oriented.
- **`SessionStore` mirroring** — duplicates IDBots' SQLite `CoworkStore`.
- **`startup()` WarmQuery** — single-use + fixed options; incompatible with multi-provider per-session env.
- **`taskBudget` (alpha)** — provider-dependent.

## 4. Known limitations of current implementation (future work)

- Auto-approve rules are persisted app-wide (not per-session); per-session overrides are in-memory only.
- Sandbox mode guest `canUseTool` (`sandbox/agent-runner/index.js`) does NOT honor auto-approve rules / permission modes / effort overrides — the guest has its own decision logic that must be updated in parallel.
- Permission mode + effort changes apply immediately in local mode; sandbox applies on next turn (guest reads stored config on resume).
- `getContextUsage()` real usage is local-mode only; sandbox uses the estimator.
- Subagent post-hoc transcripts are local-mode only (sandbox SDK runs in the VM, transcripts not on host disk).
- Cost display: DeepSeek cost is an ESTIMATE at standard (off-peak) rates — V4 has peak-hour pricing (2x, 9:00–12:00 / 14:00–18:00 Beijing time) not yet modeled. Rates live in `UsageStatsChip.tsx` (`DEEPSEEK_RATES`) — update when prices change. Non-DeepSeek proxy providers (Ollama etc.) show tokens if usage is returned, no cost.
- Cost/token stats are in-memory per active session (not persisted); they reset when the app restarts.
