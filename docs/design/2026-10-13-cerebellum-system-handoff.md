# Cerebellum System — Architecture & Handoff

Date: 2026-10-13 (roadmap expanded 2026-10-14) · Status: 6 shipped integrations live on `main` (memory re-rank, write gate, skill shortlist, block gate, effort auto, intuition tool); agreed backlog in §4 · Owner-facing docs live in `Settings > Model > Cerebellum`

This document is the handoff for the next development agent. It explains what the "cerebellum" (小脑) system is, what has been built, the design rules that must not be broken, and where it goes next.

---

## 1. What the cerebellum is

IDBots MetaBots have two model categories, mirroring Kahneman's fast/slow thinking:

| | Brain (大脑) | Cerebellum (小脑) |
|---|---|---|
| Role | Generative LLM: reasons, writes, executes | Fast decision model: ranks, gates, selects |
| First provider | Existing providers (DeepSeek, Anthropic, ...) | TypeSafe **JEV** (`jev-latest`), the first "System One" model |
| API | OpenAI/Anthropic-style chat | `POST {baseUrl}/v1/systemone` — a `state` + typed `questions` |
| Question types | — | `noul` (yes/no → 0–1 probability), `choice` (≤255 options + distribution), `score` (≤10 levels) |
| Output | Free text | Calibrated probabilities; **never generates text** |
| Pricing | input+output tokens | **input tokens only, $0.042/Mtok**, output free |

Key JEV properties (from docs.typesafe.ai): all questions in one request are evaluated **in parallel and independently** against one shared state; English question instructions work best (CJK state content is fine); 1.5s-class latency; it is literal, cannot count or compare dates, and its stated probabilities are calibrated across groups (not per-case truth) — so every consumer needs a fallback path.

**Product rule: the cerebellum is strictly optional.** With it disabled or misconfigured, every feature behaves exactly as before. It is an enhancement layer, never a dependency.

## 2. What has been built (all on `main`)

### 2.1 Settings & configuration

- `src/renderer/components/Settings.tsx` — the Model settings page has two sub-tabs: **Brain** (existing provider UI, untouched) and **Cerebellum**: enable toggle (default OFF), provider selector (single `TypeSafe JEV` entry, array-shaped for more), API key, base URL (default `https://api.typesafe.ai`), model (default `jev-latest`), and a Test Connection button.
- **Privacy notice** on the panel (zh+en): enabling the cerebellum may send memories/conversation excerpts to the cloud provider; entirely user-controlled.
- Config persists under a new top-level `AppConfig.cerebellum` key (`src/renderer/config.ts`) — deliberately NOT inside the `providers` map, so no provider-migration registry is involved.
- `src/main/libs/cerebellumConfig.ts` — `resolveCerebellumConfig(appConfig)`: the single main-process seam. Returns a normalized config or `null` (disabled / missing / malformed / empty key). **All call sites read through this; never call JEV without it.**
- `src/renderer/services/cerebellumConnection.ts` — connection test against `GET {baseUrl}/v1/models` via `window.electron.api.fetch` (→ main `session.defaultSession.fetch`, **follows the system proxy**).

### 2.2 The cerebellum client module

- `src/main/cerebellum/memoryRank.ts` — pure, Electron-free:
  - `rankMemoriesWithCerebellum({ config, fetchImpl, currentUserText, memories, timeoutMs? })` → `Map<id, noul> | null`. **Never throws.** Returns `null` on: HTTP non-200, network error, abort/timeout (default `CEREBELLUM_MEMORY_RANK_TIMEOUT_MS = 1500`), malformed payload, or **answer coverage < 80%** (`CEREBELLUM_MEMORY_MIN_ANSWER_COVERAGE`, because a partial noul map would rank unscored entries' lexical scores (≥1) above every noul (≤1)).
  - Constants: `CEREBELLUM_MEMORY_MAX_CANDIDATES = 200`, `CEREBELLUM_MEMORY_MIN_POOL = 12`.
  - One tunable English Noul instruction template (`CEREBELLUM_MEMORY_RANK_INSTRUCTIONS`) — instructions reference state by backticked dot-index path (`memories[i].text`), state carries the user's original (often Chinese) text.

### 2.3 Live integration #1 — per-turn memory recall re-ranking

- `src/main/memory/memoryPromptBlocks.ts` — `RankScopedMemoryEntriesInput.relevanceScoreById?: ReadonlyMap<string, number>`; `rankEntries` uses the map score instead of the lexical score for present ids (lexical kept otherwise); guaranteed-importance tier untouched. `buildScopedMemoryPromptBlocksDetailed(input)` returns `{ xml, injectedIds }` (injected = entries surviving ranking + char budget).
- `src/main/libs/coworkRunner.ts` — `CoworkRunnerOptions.cerebellumMemoryRanker` DI callback; `buildScopedMemoryPromptBlocksXml` (now async) fetches pools, dedupes by id, and when the ranker exists + user text non-blank + pool ≥ 12, awaits one rank call; logs `coworkLog('INFO', 'memory:cerebellumRank', { sessionId, pooled, ranked, latencyMs, used })`. Any null/throw → pure lexical.
- `src/main/main.ts` — module-level `createCerebellumMemoryRanker()`: lazy `resolveCerebellumConfig(getStore().get('app_config'))` per call (Settings edits apply next turn, no restart) + `session.defaultSession.fetch` bound. **This fetch injection is mandatory**: bare Node fetch gets HTTP 451 (region-blocked) for some networks; the Electron net stack follows the system proxy.

### 2.4 Group-task working memory (the "群任务忘事" fix)

Diagnosis (see `groupTaskDaemon` internals): assignments were only chat text inside a 20-message window; orchestration objectives and delivery deadlines were durable but never rendered; skill turns had **zero** memory reads (`disableMemoryUpdates: true` blacked out reads+writes while the daemon withheld its block on a false premise).

- `src/main/services/groupTaskWorkingState.ts` — pure `buildGroupTaskWorkingStateBlock(input)`: `<taskWorkingState>` from live steps/attempts + armed delivery clocks, overdue-first ordering, ≤12 entries / ≤2000 chars. Injected into the shared `volatileContext` of `buildTurnSystemPrompt` → every group-task turn (plain, skill, chair planning/report) sees it.
- `src/main/services/orchestratorCoworkBridge.ts` + `main.ts` — group-task skill turns now pass `memoryReadOnly: true` instead of `disableMemoryUpdates: true` (reads restored, writes stay off; the paid-order mode). New `memory_read_only_automation` system-prompt profile in `coworkRunner.ts` keeps the write-inviting Memory STRATEGY section unmounted.
- `src/main/services/groupTaskDaemon.ts` — owner-scope memory block now mounts on **both** paths; optional `cerebellumMemoryRanker` dep re-ranks the daemon block (same contract/limits). `buildScopedMemoryBlockFor` returns `string | Promise<string>` — **fully synchronous when the ranker is unwired**: the daemon tick's detached-job interleaving is timing-sensitive and one added microtask hop deterministically tripped the silent-chair re-drive test. Keep this shape.
- Private-chat and OpenTeam guest daemon bindings deliberately still use the blackout (external-facing sessions; flip only with a privacy review).

### 2.7 Memory write gate (roadmap #1 — shipped on `feat/cerebellum-memory-write-gate`)

- `src/main/cerebellum/memoryWriteGate.ts` — pure, Electron-free, same shape as `memoryRank.ts`: `gateMemoryWriteWithCerebellum({ config, fetchImpl, userText, assistantText, explicitOnly, timeoutMs? })` → `boolean | null`. **Never throws.** `true`/`null` = proceed to the brain extraction (fail-open — a broken gate can only cost money, never memories); `false` = skip the brain call for this turn. One Noul question (`worth_remembering`), English instructions with two variants (implicit vs explicit-only mode), state carries the turn's user/assistant excerpts in the original language (capped 1200/400 like the extraction pass). Threshold `CEREBELLUM_MEMORY_WRITE_GATE_THRESHOLD = 0.5` (cookbook gate at P≥0.5); timeout 1500 ms.
- `src/main/libs/coworkMemoryJudge.ts` — `judgeTurnMemoryExtraction` now consults an injectable gate (`setCerebellumMemoryWriteGate`, same module-setter pattern as `setMemoryJudgeBrainResolver`) between the result cache and `runTurnMemoryExtractionDefault`. `gate === false` returns `[]` (the caller already treats that as "nothing extracted"); the skip verdict is deliberately NOT cached so Settings toggles re-evaluate fast. The injected test runner stays the executor itself (bypasses the gate) — seam ordering is locked by a test.
- `main.ts` — `createCerebellumMemoryWriteGate()` factory (lazy `resolveCerebellumConfig` per call + `session.defaultSession.fetch`, identical to the ranker), wired once at startup next to `setMemoryJudgeBrainResolver`. Logs `memory:cerebellumWriteGate` with verdict + latency only — never turn text.
- `judgeMemoryCandidate`'s boundary brain calls are NOT gated (rare, cached, per-candidate) — possible follow-up.
- `scripts/cerebellum-write-gate-eval.mjs` — offline eval harness (same pattern as the rank eval): embedded 23-case labeled Chinese dataset, confusion matrix with FN (lost memory) called out, threshold sweep, `--explicit-only` mode, `--cases <json>`, `--dry-run`. First live run (implicit mode, jev-1.13.0): **23/23 — memorable noul 0.57–0.98 all proceed, skip 0.03–0.08 all rejected**; explicit-only variant 10/10. Threshold 0.5 sits in the wide gap (0.3–0.5 → FN=0; ≥0.6 starts losing borderline "ongoing interest" turns). ≈$0.00002 per gated turn, ~800 ms latency.

### 2.8 Skill shortlist (roadmap #2 — shipped on `feat/cerebellum-skill-shortlist`)

- `src/main/cerebellum/skillShortlist.ts` — pure, Electron-free: `rankSkillsWithCerebellum({ config, fetchImpl, currentUserText, skills, timeoutMs? })` → full ranking sorted best-first or **null, never throws**. One JEV **Choice** question (`best_skill`, ≤255 options): `state = { user_message }` (original language), `criteria` keyed by skill id with `name: description` (descriptions capped at 320 chars). Answer parsing: `answers.best_skill.probabilities` (unknown keys skipped, values clamped, sorted desc) with a fallback to the top-level `choice` when the distribution is unusable. Constants: timeout 1500 ms, `TOP_K = 3`, `MIN_POOL = 12` (smaller catalogs stay model-scannable, no call), `MAX_OPTIONS = 255`. `buildSkillShortlistBlock` renders the `<skill_shortlist>` volatile block: top-3 lines + `Suggested skill:` one-liner; probabilities are deliberately NOT rendered (calibrated across groups, not per-case).
- `coworkRunner.ts` — new `cerebellumSkillRanker` DI dep (`{ currentUserText, metabotId }` → top-3 entries or null). In `buildVolatileContextPrompt` the rank promise **starts before the memory sections** (overlapping the memory re-ranker's own JEV round-trip, so worst case stays one 1.5 s budget, not two) and is awaited at the skills-catalog section; it only fires for `skillsCatalogMode === 'volatile'` sessions with non-blank text. The `skills-catalog` block itself is untouched — byte-stable for its content-hash dedup — and the shortlist rides as a separate `skills-shortlist` section. Null/throw → byte-identical output to no ranker (locked by tests). Logs `skills:cerebellumShortlist` (runner: sessionId + used + ids; closure: pool/latency).
- `main.ts` — `createCerebellumSkillRanker()` factory (lazy config + `session.defaultSession.fetch`); the closure resolves the catalog's own visible set via `skillManager.listSkillsForMetabot(metabotId)` so the shortlist can never mention a skill the catalog omits. Wired once into the `CoworkRunner` construction.
- Privacy notice widened (zh+en, `i18n.ts cerebellumPrivacyNotice`): installed skills' names/descriptions are now explicitly listed as content that may leave the machine.
- `scripts/cerebellum-skill-shortlist-eval.mjs` — offline eval harness: embedded 48-skill synthetic roster (zh+en) + 12 labeled Chinese queries, top-1 accuracy / recall@3, `--roster`/`--queries` custom JSON, `--dry-run`. First live run (jev-1.13.0): **top-1 12/12, recall@3 12/12 — every labeled skill ranked #1 with p=1.00**; ≈2.2K input tokens ≈ **$0.0001 per ranked turn**, ~800 ms latency.

### 2.9 Volatile block gate (roadmap #3 — shipped on `feat/cerebellum-volatile-block-gate`)

- `src/main/cerebellum/volatileBlockGate.ts` — pure, Electron-free: `gateVolatileBlocksWithCerebellum({ config, fetchImpl, currentUserText, timeoutMs? })` → `Record<blockKey, boolean> | null` (true = inject, false = skip) or **null, never throws**. One request, one Noul per gateable block, all evaluated in parallel against `state = { user_message }` (original language; block CONTENT never leaves the machine — each question describes its block CATEGORY). Gateable blocks (single source, `CEREBELLUM_VOLATILE_GATE_SECTION_KEYS`): `experience`, `twin-impression`, `knowledge-bases`, `remote-services`. Deliberately NOT gated: `memory` (alwaysInject by design), `browser`/`goal` (small, live, user-explicit), `skills-catalog` (the shortlist owns that surface). Thresholds `CEREBELLUM_VOLATILE_GATE_THRESHOLDS = 0.35` per block — deliberately BELOW 0.5: a lost block is worse than a carried one, so the gate skips only when fairly confident the block is irrelevant. Within a usable payload a missing/unusable per-block answer resolves to inject (fail-open per block, not per turn).
- `coworkRunner.ts` — new `cerebellumVolatileBlockGate` DI dep. In `buildVolatileContextPrompt` the gate promise **starts at function entry** (overlapping the memory re-ranker's own JEV round-trip) and is awaited at the first gated consumer (after the memory section; memory-disabled profiles await it at the remote-services site). `shouldInjectVolatile(key)` skips a gated push only on an explicit `false` for a gateable key — verdicts naming ungated keys are ignored (immunity locked by a test). Null/throw → output byte-identical to no gate (test-locked). Logs `volatileBlocks:cerebellumGate` (runner: sessionId + verdicts; closure: skipped keys + latency). After the #2 merge, the function-entry block hosts BOTH cerebellum promises (skill shortlist + block gate), all overlapping the memory re-ranker — still one 1.5 s budget.
- `main.ts` — `createCerebellumVolatileBlockGate()` factory (lazy config + `session.defaultSession.fetch`), wired into the `CoworkRunner` construction.
- `scripts/cerebellum-volatile-gate-eval.mjs` — offline eval harness: embedded 17-case labeled Chinese dataset (none/kb/remote/experience/twin/mixed), per-block confusion matrix with LOST (FN) called out, threshold sweep, `--cases`, `--dry-run`. First live run (jev-1.13.0) after correcting two over-aggressive labels: **FN=0 across all four blocks, 53/68 block injections saved (78%), 2 conservative keeps** (same cost as status quo). Threshold sweep: FN=0 throughout 0.2–0.5; 0.65 starts losing. ≈690 input tokens ≈ $0.00003 per gated turn, ~250 ms/query.
### 2.10 Reasoning-effort auto selection (roadmap #11 — shipped on `feat/cerebellum-effort-auto`)

- `src/main/cerebellum/effortSelector.ts` — pure, Electron-free, same shape as the other modules: `selectEffortWithCerebellum({config, fetchImpl, currentUserText, timeoutMs?})` → the {off, low, high, max} probability distribution or **null, never throws**. One Choice question (`effort_level`), English instructions kept byte-identical to `scripts/cerebellum-effort-eval.mjs` (tune them together). Solo-call timeout 1000 ms (observed 200–665 ms). `resolveAutoEffortRung(distribution, {assistantMode})` is the policy: assistant mode escalates only when P(high)+P(max) ≥ `CEREBELLUM_EFFORT_ESCALATION_THRESHOLD` (0.5), then takes the heavier of the two — casual chat stays off; professional mode takes the argmax with the LOWER rung winning ties.
- `coworkRunner.ts` — new `cerebellumEffortSelector` DI dep. The runner kicks the JEV promise BEFORE `buildVolatileContextPrompt` (overlapping that window's cerebellum round-trips) and awaits it at the effort resolution: sessions without an explicit pick resolve `autoEffortRung` first; the rung flows through BOTH the primary route and the GT-02 fallback-brain chain. Null keeps the legacy default chain byte-identical (assistant mode → off). Logs `effort:cerebellumSelect` with the verdict + probabilities (numbers only, never text).
- `main.ts` — `createCerebellumEffortSelector()` factory (lazy `resolveCerebellumConfig` + `session.defaultSession.fetch`, logs used + latency), wired into the `CoworkRunner` construction.
- UI: the picker's "Default" rung is renamed **Auto** (`modelPickerEffortDefault` zh 自动 / en Auto, desc explains the cerebellum + fallback). Assistant mode's unpicked display is the Auto rung instead of 'off' (`effortDisplayForPick` + `CoworkSessionDetail` both return null); the recent hide-'off'-label trigger behavior is unaffected. Zero storage migration: null effortOverride means auto everywhere, and with the cerebellum disabled the semantics are exactly the old default chain.
- Tests: `tests/cerebellumEffortSelector.test.mjs` (12) + updated `tests/coworkComposerEffortDefault.test.mjs` source-contract assertions (override → autoEffortRung → assistant off ordering on both chains).
- **Session stickiness (Phase 2, shipped)**: `resolveStickyAutoEffortRung` wraps the policy with a per-session sticky entry (`CEREBELLUM_EFFORT_STICKY_WINDOW_MS` = 10 min). A bare "继续" mid-coding-session classifies off on its own but rides the armed high/max rung; the window refreshes only on a FRESH escalation (sticky-sustained turns do not extend it), so a casual interlude rides high for at most 10 minutes. The runner holds the map (`autoEffortStickyBySession`, pruned past 128 entries) and logs `sticky: true`.
- **Adaptive-thinking routes — decided, no code**: on Anthropic-wire routes with `forceAdaptiveThinking` (Ark GLM etc.) an escalated verdict ALREADY rides adaptive thinking (the declaration sends `thinking:{type:'adaptive'}` + `output_config.effort` for every enabled rung), and `off` sends the explicit disabled state — so the escalation path is inherently adaptive there with zero extra wiring. Skipping the JEV call on those routes (auto = always-adaptive) was evaluated and declined: it saves ~600 input tokens but forks the auto mechanism per wire, and adaptive thinking's casual-turn depth on every gateway is unvalidated — the uniform JEV policy is the validated one. Revisit only with live per-gateway evidence.

### 2.11 Intuition tool — the brain-callable cerebellum (owner's initiative, shipped on `feat/cerebellum-intuition-tool`)

The first cerebellum surface the MetaBot itself controls: the `intuition` inline tool lets the brain ask the fast decision model for calibrated judgments (noul / choice / score) on content IT chooses, mid-turn. The infra integrations (#1–#3, #11) stay deterministic in the infra — this tool serves ad-hoc judgments only the brain knows it needs (candidate picking by soft fit, claim-vs-context likelihood, calibrated ratings). Rationale: models keep getting smarter but still lack a fast intuition layer, and smarter models will use such a tool more judiciously over time.

- `src/main/cerebellum/intuitionTool.ts` — pure, Electron-free: `askCerebellumIntuition({config, fetchImpl, context, questions, timeoutMs?})` → parsed answers + input tokens, or **null, never throws** (blank context, HTTP/network error, abort/timeout, malformed payload). `validateIntuitionInput` enforces hard caps on every bot-authored dimension (context ≤ 6000 chars, ≤ 6 questions, instructions ≤ 600 chars, choice options 2–24 with slug ids, score levels 2–10 — clear teaching errors, never silent truncation). Question shapes follow the JEV primitives: noul → `criteria {true,false}` (defaults), choice → `criteria` keyed by option id, score → ordered `criteria` level array (low → high; answers carry `score` as a probability-weighted position between levels). Timeout 3000 ms — an explicit tool call the model chose gets a bigger budget than the invisible 1500 ms injections.
- `coworkRunner.ts` — the tool mounts in `buildSessionInlineTools` when BOTH the sync availability probe (`cerebellumIntuitionAvailable` DI) passes and the session is `sourceChannel === 'cowork_ui'` (phase 1: the owner's own sessions; external-facing surfaces keep the established privacy posture). The tool DESCRIPTION is the built-in teaching text — WHEN to use (soft-fit candidate picking, claim-likelihood, calibrated ratings), WHEN NOT (computable facts, lookups, text generation, substitute-for-reasoning), HOW (atomic questions, English wording, one-line option descriptions, ordered levels), plus the standing caveat that probabilities are calibrated across groups, not per-case guarantees — every answer block repeats it. Guardrail: rolling window max 3 calls/60 s per session (`cerebellumIntuitionCallsInWindow` on ActiveSession, reset lazily on window expiry — no per-turn hooks). Null verdicts return an honest "no verdict … do not retry immediately" instead of retry-baiting. Validation errors surface verbatim to teach the model to re-ask within bounds. Logs `cerebellum:intuition` (question count + types + latency + tokens; never context or question text).
- `main.ts` — mount probe uses the sync `resolveCerebellumConfig` (best-effort; a free-relay outage degrades to "no verdict" at call time, not a missing tool); the executor goes through `resolveCerebellumCallContext()` so the free relay's key-retry fetch applies like every other call site.
- Privacy notice widened again (zh+en): "content the bot submits for judgment via its intuition tool" is now explicitly listed — the bot decides what to send, so the notice says so.
- Tests: `tests/cerebellumIntuitionTool.test.mjs` (12) — validation caps, per-type request shapes, answer parsing/clamping, fail-open + deadline, mount gating (availability AND cowork_ui), teaching-text contract on the description, caveat passthrough, honest null verdicts, rolling-window cap + lazy reset.
- Live validation note: the three question shapes are each proven against the real API by the earlier feature evals (noul: write-gate eval; choice: shortlist + effort evals; score: docs-verified shape used by effortSelector). A full live smoke of THIS module was attempted but the free relay returned 429 `free_quota_exhausted` — the fail-open null path is exactly what shipped. Re-run the smoke (scripts pattern: require dist module, relay baseUrl + mrk_ key from app config) once quota resets.
- Follow-ups: observe `cerebellum:intuition` logs for the models' real question quality before widening past cowork_ui; consider a small vetted question-pattern library in the tool description if quality is erratic.


### 2.12 Free relay provider & the shared call context (`services/jevRelayService.ts`)

The provider landscape grew past §1's original single provider:

- **`typesafe-jev`** — the paid TypeSafe API (`https://api.typesafe.ai`), user-supplied key.
- **`idbots-jev-free`** (`CEREBELLUM_FREE_PROVIDER`) — the official free relay at `https://www.metaso.network/assist-open-api/v2/assist/llm/jev`, key bootstrap via `resolveJevRelayCredentials()` (relay `mrk_` keys), quota-limited (HTTP 429 `free_quota_exhausted` when spent). The DEFAULT since `feat/jev-free-defaults` — assume most users ride it.

Both speak the same `/v1/systemone` wire format. The seam that matters for every NEW call site in `main.ts`:

- `resolveCerebellumRuntimeConfig(appConfig)` — async; the sync `resolveCerebellumConfig` plus relay-key resolution for the free provider (bootstrap failure → null → feature off for that call).
- `resolveCerebellumCallContext()` — the one-liner every executor uses: returns `{ config, fetchImpl }` where `fetchImpl` is the raw Electron net fetch for `typesafe-jev`, or `createJevRelayFetchWithKeyRetry(...)` for the free relay (re-bootstraps once on a 401, no retry storms).
- Sync mount probes (e.g. tool registration) may use the sync `resolveCerebellumConfig` — best-effort only; a relay outage then degrades to "no verdict" at call time, which is the correct fail-open.

**The pre-relay pattern (`resolveCerebellumConfig` + bare `session.defaultSession.fetch`) is now WRONG for executors** — a free-relay config authenticated that way gets 401. Pure modules stay fetchImpl-injected and provider-agnostic; only the main.ts wiring changes.

Live-eval note: the relay is quota-metered; when exhausted, live evals and smokes return 429 and every call site's fail-open path is what ships. The metaso relay does not need the local proxy (the §5 proxy note applies to `api.typesafe.ai` only).

### 2.13 Knowledge hot-layer ranking (roadmap #4 — shipped on `feat/cerebellum-knowledge-hot-rank`)

- `src/main/cerebellum/knowledgeHotRank.ts` — pure, Electron-free: `rankKnowledgeWithCerebellum({ config, fetchImpl, currentUserText, entries, timeoutMs? })` → `Map<id, noul> | null`. **Never throws.** One Noul per point (`kn_i`) against `state = { current_message, knowledge: [{ id, text }] }`. `text` is `[kind] topic: summary`, whitespace-collapsed, capped at 500 chars. The request takes the newest 40 active points (`CEREBELLUM_KNOWLEDGE_MAX_CANDIDATES`); answer coverage below 80% discards the whole map, because an unscored point would otherwise sink below every noul. Timeout 1500 ms. English instructions; the user's message and the knowledge text stay in the original language. `listKnowledge`'s `updated_at DESC` order is unchanged — it is the recency fallback.
- `knowledgePromptBlocks.ts` — `orderKnowledgeEntriesForPrompt` / `buildKnowledgeBlock(..., relevanceScoreById)`. A present score replaces recency for that id; ids the map does not mention sink below every scored id and keep their relative order. No map, or an empty map, leaves the newest-first slice byte-identical.
- `coworkRunner.ts` — `cerebellumKnowledgeRanker` DI. The promise starts at `buildVolatileContextPrompt` entry so it overlaps the memory re-rank and the block gate (still one 1.5 s budget). It is awaited only when the experience section actually renders; a gate that skips `experience` does not wait on the call. Pools smaller than 9 (`CEREBELLUM_KNOWLEDGE_MIN_POOL`) skip the call — the hot layer already shows every active point. Null/throw → newest-8, byte-identical to no ranker (test-locked). Logs `knowledge:cerebellumRank` with pooled / ranked / latency / used only.
- `main.ts` — `createCerebellumKnowledgeRanker()` goes through `resolveCerebellumCallContext()` and is wired into the `CoworkRunner` construction. The group-task daemon does not render this hot layer, so it does not get the dep.
- Privacy notice widened (zh+en, `i18n.ts cerebellumPrivacyNotice`): distilled knowledge points (topics and summaries) are now listed.
- `scripts/cerebellum-knowledge-hot-rank-eval.mjs` — embedded 16-point Chinese set ordered newest-first (the newest 8 are distractors; the labeled points sit older), recall@8 against that recency baseline, plus a noul sweep that is calibration-only — the product has no cutoff, the noul is a rank key. ## 3. Design rules (do not break)

1. **Never block a turn on the cerebellum.** 1.5 s hard timeout, null on any failure, silent lexical/code fallback. The cerebellum must be droppable mid-flight with zero user-visible effect.
2. **Never call JEV without resolved config** and never log memory text or the API key. Executors go through `resolveCerebellumCallContext()` (§2.12); only sync mount probes may use the sync `resolveCerebellumConfig`.
3. **`fetchImpl` comes from `resolveCerebellumCallContext()`** — the raw Electron net fetch for the paid provider, the key-retry relay wrapper for the free provider (§2.12). Binding bare `session.defaultSession.fetch` to a free-provider config 401s. Bare Node fetch is additionally region-blocked for `api.typesafe.ai` (HTTP 451).
4. Keep question instructions in **English**; keep the user's original-language text in `state`.
5. Don't ask JEV what code can compute (counting, dates, thresholds) — compose atomic judgments in code instead.
6. The `enabled` toggle is the user's global consent for sending memory content to the provider; new call sites must not widen what is sent beyond what the notice describes without a new notice.
7. Repo conventions (AGENTS.md): pnpm only (Node 24 via nvm: `export PATH="$HOME/.nvm/versions/node/v24.13.1/bin:$PATH"`); worktree-per-branch from `main`; `git merge --no-ff` into main; dev journal on-chain via the `metabot-post-buzz` skill after every commit; never push unless asked.
8. **New test files under `tests/` are git-ignored by default** — `tests/*` is ignored and each suite is allowlisted individually; add `!tests/<name>.test.mjs` next to the other cerebellum entries or your file will silently never be committed.
9. **Pure cerebellum modules carry no runtime imports** (type-only imports are fine — they are erased): unit tests load `src/main/cerebellum/*.ts` directly with Node type stripping, which requires extension-ful ESM specifiers. Inline tiny helpers instead of importing them (see `truncateUtf16Prefix` in `skillShortlist.ts`).

## 3.5 How to add a new cerebellum integration — the recipe

Every shipped integration (§2.7-§2.11) follows the same shape; copy it:

1. **Pure module** `src/main/cerebellum/<feature>.ts` — Electron-free, `fetchImpl`-injected, never throws, returns the verdict or `null` on any failure (fail-open: null always means "behave exactly as before"). English question instructions; original-language user text in `state`; hard caps on every caller-authored dimension. No runtime imports (rule 9).
2. **DI seam** — coworkRunner option (or a module setter like `setCerebellumMemoryWriteGate` for libs). Fire the JEV promise as early as possible (parallel with the other per-turn cerebellum calls — the shared budget stays one 1.5s window) and await at the first consumer.
3. **main.ts wiring** — executor via `resolveCerebellumCallContext()` (§2.12); log a new `xxx:cerebellumYyy` tag with verdict/latency/ids only — never content.
4. **Privacy check** — does the call send any content category the notice doesn't list? If yes, widen `i18n.ts cerebellumPrivacyNotice` (zh+en) in the same change.
5. **Tests** `tests/cerebellum<Feature>.test.mjs` — pure-module contract (request shape, parse, every failure mode, caps) + compiled-DI integration (null/throw reproduces the ungated baseline byte-for-byte; mount gating). Add the file to the `.gitignore` allowlist (rule 8). Run `pnpm run compile:electron` first — suites import compiled code.
6. **Offline eval** `scripts/cerebellum-<feature>-eval.mjs` — labeled real-shaped Chinese dataset, the metric that matters for THIS feature (FN/lost-X for gates, recall@k for rankings), threshold sweep, `--dry-run`. Run it LIVE before shipping thresholds; keep the script's question wording byte-synced with the module.
7. **Docs** — new §2.x subsection + roadmap row update in this file.
8. **Journal** — commit (`feat: ...`), then post the on-chain dev journal via the `metabot-post-buzz` skill and reference the pinId in the commit message.
