# 运营手册 — 流量系统后台操作指南

适用对象：IDBots 流量系统（GasFee 流量化）的运营人员。本手册只讲后台操作，
不需要懂区块链。开发/接口细节见同目录其他文档（backend-spec*.md 等）。

> 术语：本文「流量」= 用户账户里的字节数（bytes）。1 KB = 1000 B，
> 1 MB = 1000 KB，1 GB = 1000 MB。基准价目：¥10 = 100 MB = 100,000,000 B。

---

## 1. 登录与页面总览

**入口**

| 环境 | 后台地址 | 说明 |
|---|---|---|
| 生产 | `https://www.metaso.network/assist-open-api/admin/` | 生产 admin token（与现网 LLM 后台同一个） |
| 测试 | `http://47.76.58.120:7882/admin/` | 测试 token，测试库 `assist_db_test`，随便造数据 |

登录页输入 admin token 即可进入。**Token 保管规则**：不外传、不贴进聊天记录
或代码仓库、不写进文档；泄露后立即找后端团队轮换。

登录后左侧/顶部有 6 个页面：

| 页面 | 用途 |
|---|---|
| Dashboard | 流量总览（总量、消耗等汇总数据） |
| Accounts | 账户查询（按 GlobalMetaID/地址查用户余额、绑定、用量） |
| Pricing | 价目表管理（套餐的金额 ↔ 流量） |
| Orders | 充值订单列表（真实支付上线前基本只有测试数据） |
| Free Grant | 免费领取活动：开关、额度、领取记录 |
| Codes | 充值码：生成、导出、作废、统计 |

## 2. 免费领取活动（Free Grant 页）

新用户可以在客户端（IDBots 设置 → 流量，余额下方）点「免费领取 10M 流量」，
一个账户终身只能领一次。

**页面字段**

- `enabled` 勾选框：活动总开关。**默认关闭**。勾选 + 保存即全网开放领取；
  取消勾选立即停止新领取（已领到账的不受影响）。
- `grantBytes` 单次领取字节数：默认 `10000000`（= 10 MB）。改动后**只影响
  新领取**，历史记录不变。
- 领取记录表：账户、领取字节、来源客户端、时间。

**运营场景**

1. **正式开放**：确认价目/额度 → 勾选 enabled → 保存。不需要发版，即时生效。
2. **调整额度**：改 grantBytes → 保存。建议在活动低峰期改，避免用户看到
   两个不同数字。
3. **遇到羊毛**（同一批地址集中领取）：
   - 第一步：立即取消 enabled 保存（最快止损）；
   - 第二步：看领取记录确认来源客户端（正常应只有 `idbots`）；
   - 第三步：联系后端团队开启更严的防刷参数（IP 限频 / 客户端共享 token），
     然后再重新开放。
4. **活动下线**：取消 enabled 保存即可，历史数据保留。

## 3. 充值码（Codes 页）

真实支付接入前，充值靠「充值码」：用户输入一次性码，获得码对应的流量。

**页面区块**

- 顶部统计卡：Generated / Unused / Used / Disabled（及未兑出总字节数）。
- 生成表单：`count` 数量、`trafficBytes` 单码流量（bytes）、`expiresAt`
  有效期（留空 = 永不过期）、`note` 备注 → 生成。
- 批次列表：每批有 `Export unused`（导出未用码 CSV）和 `Revoke`（整批作废）。
- 码列表：可按批次/状态/码内容筛选；单码可 `Disable`。

**运营场景**

1. **发一批码**（如活动赠码）：生成（例如 1000 个 × 100 MB）→ 立即
   `Export unused` 导出 CSV → 分发。生成后页面只展示一次，务必当场导出。
2. **作废**：码泄露/渠道异常 → 批次 `Revoke`（该批未用码全部失效，已用的
   不受影响）；个别码单独 `Disable`。
3. **查账**：筛选批次 → 看每码状态、`usedAccountId`（谁兑的）、`usedAt`。

**行为说明**（不是 bug）：

- 一码只能成功兑换一次；第二个人输入 → 提示已使用。
- 同一个用户重复输入**自己已经兑过的码** → 提示成功但不会重复到账
  （幂等保护）。
- 用户端入口：IDBots 设置 → 流量 → 充值码输入框。

## 4. 价目表（Pricing 页）

套餐 = `planId` + 链（目前 mvc）+ 支付币种（CNY）+ 金额 + 流量字节 + 状态。

- 修改/上下架只影响**新下单**；已生成的订单不受影响。
- 真实支付上线前，价目表主要用于：①客户端展示 ②确定充值码面额的参考。
- 定价建议与后端团队对齐（要覆盖矿工费采购成本，见 §6）。

---

## 5. 动态费率（fee rate）

赞助代付的矿工费率是后端可配置的动态值，**当前没有独立后台页面**，调整
由后端团队执行。运营如需调整（例如链上费率大涨），直接提给后端团队，并
同步考虑价目表是否需要跟着调。

---

## 6. 资金池与成本（重要概念）

用户充的钱 → 团队用低于售价的成本采购 SPACE → 充入 sponsor 代付池 →
用户上链时按字节从池里代付。运营要盯两件事：

- **代付池健康度**：后端有健康检查（warning / critical 阈值）。池快空时
  会开始影响用户上链成功率（用户端报流量/赞助相关错误）。
- **采购**：目前是人工环节（自动化采购在规划中）。池健康度告警时联系
  后端团队安排采购补池。

## 7. 常见问题（FAQ）

- **Q：用户说按钮消失了？** 领取按钮只有「未领过 + 活动开着」才显示，
  领完即消失，正常。
- **Q：用户余额怎么变少了？** 每次链上操作按交易字节扣流量；后台
  Accounts 页可查该账户明细（账本）。
- **Q：测试环境随便玩？** 是，测试实例数据独立（`assist_db_test`），
  不会影响生产。
- **Q：改了 grantBytes 为什么旧用户没变？** 领取是快照制，改额只对
  新领取生效。
